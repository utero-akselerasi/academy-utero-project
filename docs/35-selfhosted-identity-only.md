# Migrasi identitas minimal ke backend mandiri

Keputusan 15 Oktober 2026: **jangan migrasikan seluruh database dan storage Supabase**. PostgreSQL target dibuat baru dan dimigrasikan hanya untuk skema aplikasi serta seed definisi role/permission. Data yang disalin dari sumber terbatas pada akun **yang mempunyai `utero_academy.user_profiles`**, yakni UUID internal, email, nama lengkap, nomor telepon, status aktif, dan timestamp profil. Satu `auth.identities` email baru dibuat per akun agar alur aktivasi backend lokal berfungsi.

Tidak disalin: hash password lama, status verifikasi email lama, sesi, token, metadata auth lama, penugasan role lama, avatar/file, objek storage, tabel domain, data aktivitas, dan histori audit. `avatar_path` menjadi `NULL`; file lama tidak dapat diakses di backend baru. Pengguna lain dalam instance Supabase bersama tanpa profil Academy **tidak ikut**.

## Urutan aman

1. Siapkan PostgreSQL 17 target **kosong** dan jalankan service `migrate` dengan env file operator di luar repository. Ini membuat skema serta definisi lima role/permission lokal; bukan menyalin data bisnis. Simpan backup sumber dan tetapkan snapshot/freeze writer; snapshot lama tidak boleh dipakai untuk cutover final.
2. Siapkan `SOURCE_DATABASE_URL` kredensial **read-only** dan `ACADEMY_MIGRATION_DATABASE_URL` ke service `postgres:5432/academy` yang masih kosong. Isi `CONFIRM_USER_PROFILE_COPY=copy-user-profiles-only` hanya pada saat eksekusi. Jangan isi `CONFIRM_DATABASE_COPY` maupun `CONFIRM_STORAGE_IMPORT`.
3. Jalankan `docker compose --env-file <file-operator> -f docker-compose.backend.yml --profile migration run --rm user-profile-copy`. Script menolak database sumber/target yang sama, sumber tanpa profil Academy, email duplikat, serta target yang sudah memiliki user/profil/role assignment. Penulisan target satu transaksi, tanpa operasi truncate.
4. Sebelum bootstrap, audit jumlah profil, email, `auth.identities`, password/konfirmasi (harus nol), `utero_academy.user_roles` (harus nol), `academy_storage.objects` (harus nol), dan tabel domain (harus kosong kecuali seed/migrasi yang sengaja dibuat). Periksa total dan checksum yang dicetak script; jangan menyimpan daftar email ke log publik.
5. Pilih **satu akun operator Academy** dari hasil migrasi, bukan otomatis akun pertama. Isi `BOOTSTRAP_SUPER_ADMIN_EMAIL`, `BOOTSTRAP_SUPER_ADMIN_PASSWORD` (16–128 karakter acak) dan `CONFIRM_BOOTSTRAP_SUPER_ADMIN=bootstrap-initial-super-admin`; jalankan service `bootstrap-super-admin` dari file env terlindung. Perintah menolak bootstrap kedua, memberi role `super_admin` kepada akun tersebut, dan menetapkan password baru yang tidak berasal dari Supabase.
6. Login sebagai super-admin. Tetapkan role pengguna lain dari halaman **User dan Role** setelah verifikasi identitas dan hak akses. Domain profile `admin`/`intern` dibentuk saat role diberikan; hubungan sekolah/lamaran lama **tidak** tersedia dan harus diisi kembali sesuai kebutuhan. Setelah SMTP production teruji, pilih **Kirim Aktivasi** pada akun berlabel **menunggu aktivasi**. UI memanggil `POST /v1/super-admin/users/:id/activate`; endpoint hanya menerima akun impor yang belum memiliki password/konfirmasi, wajib memiliki role, memakai token sekali pakai berlaku satu jam, lalu pengguna menentukan password baru pada `/register/invite`.
7. Jalankan UAT semua lima role, batas akses lintas pengguna, email activation, TLS/SMTP, backup/restore serta health production sebelum publikasi. Gate lama di `docs/34-production-readiness-status.md` mensyaratkan migrasi penuh dan **tidak boleh** dipakai sebagai bukti GO strategi ini. Tetap NO-GO sampai evidence strategi baru dan approval operator/reviewer lengkap.

## Rehearsal 15 Oktober 2026

Dump sumber **14 Oktober 2026 08:33 WIB** dipakai hanya pada clone terisolasi, bukan sumber final. Target baru pada WSL ext4, tidak membuka port host. Impor menghasilkan **29 user + 29 profil**, lima referensi avatar dibersihkan. Pemeriksaan SQL: 29 identitas email baru; **0** hash password, konfirmasi, penugasan role sumber, row domain sampel, dan objek storage. Bootstrap satu akun rehearsal berhasil dan login API HTTP 200. Tidak ada perubahan pada database atau trafik production.

Sebelum production, butuh snapshot identitas terbaru, pemilihan operator bootstrap, kredensial production terpisah, SMTP yang benar-benar bekerja, domain/TLS, serta penilaian dampak bisnis dari database dan file historis yang sengaja tidak dimigrasikan.
